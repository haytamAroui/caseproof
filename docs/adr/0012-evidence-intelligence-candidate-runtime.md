# ADR 0012 — Evidence Intelligence candidate runtime

Status: implementation proposal under the owner's 23 October 2026 instruction to build the integrated extraction milestone. Supersedes ADR 0011 only for permitting a thin **experimental construction observation vocabulary/test consumer** beside finance. It does not authorize a construction product launch, legal rulepack, shared AZComply runtime, production migration, provider call with customer data, or approval route.

Keep the Kernel unchanged and pure. `application/extraction` owns typed candidate contracts, bounded global scout/targeted, segmented and optional four-pass execution, exact quotation/entity/source checks, plugin validation, reconciliation and coverage projection. `domains/finance` and `domains/construction` supply independent conservative signal validators; they do not import the runtime or each other. This is a narrow structural protocol, not DomainPack or a general agent framework. The import checker now guards the new sector boundary.

`apps/api/requesty_extraction.py` implements the existing application port using stdlib HTTP against Requesty's EU gateway. Configuration requires an explicit concrete Requesty model; no hardcoded model, SDK dependency, direct alternate-provider integration, policy route or application fallback. Existing Requesty key/paid-model environment variable names can be reused; no credentials are copied from AZComply. Gateway region alone does not establish inference residency; organization/model policies must be independently reviewed before real documents are sent. Endpoint/request format: [Requesty documentation](https://docs.requesty.ai/), [regional routing](https://www.requesty.ai/product/routing).

Every call has a persisted input hash and dispatch checkpoint. Raw **valid provider reply envelopes** persist before extraction JSON validation; transport ambiguity blocks retry. Malformed HTTP/provider envelopes fail closed without a reusable candidate payload. Received responses replay without another provider call. No auto-reset of dispatched/unknown steps. Event+checkpoint changes are atomic in the disposable PostgreSQL adapter, with synthetic membership checks on every operation. See [database review specification](../tasks/EI-001.md). This is not installed on Supabase and is not signed identity propagation.

Confirmed entity/source ranges and required claim slots originate independently of LLM discovery. Scout entities/relationships remain proposals. A model cannot confirm its own boundaries or expand case scope. Multi-source business entities use multiple explicit source boundaries; relationship proposals are never proven causation. Exact representation-bound offsets are found/checked server-side; repeated quotes require disambiguation. Wrong ownership, unknown signals, negation/conditional language and incomplete representations remain blocked/review-only. Lexical validation means consistency with a registered observation vocabulary, **not semantic truth or authoritative support**. Every slot remains unverified/missing/conflicting until review; no extraction output becomes approved or sufficient.

Kernel projection reuses existing finding statements, exact quote fidelity, model-attributed semantic proposals with `NOT_ASSESSED` sufficiency, and coverage manifests. It is reproducibly rehydrated from checkpoints, not a second authoritative CaseFacts store. There are no writes to accepted finding/decision tables and no human decision implementation in this milestone.

Limitations: UTF-8 representations only; parser/vault intake authorization remains upstream. No PDF/OCR/UBL/spreadsheet adapter, reviewer UI, complete durable Kernel graph or offline dossier export is newly implemented. Four-pass discovery is experimental opt-in; no quality/cost improvement claimed. Scripted fixtures measure deterministic safety/recovery behavior, never live extraction precision/recall. Requesty account routing and live provider evaluation remain unmeasured. Existing finance comparison is preserved; candidate extraction does not infer monetary basis or overwrite balances.

Roll back by reverting this additive runtime/adapter and dropping only the disposable CI database. No existing Kernel public contracts, canonical migrations, permission catalog or public API routes change.

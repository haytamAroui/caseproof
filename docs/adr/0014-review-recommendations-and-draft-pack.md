# ADR 0014 — frozen review recommendations and draft evidence pack

Status: implementation proposal under the owner's next combined PR instruction. Stacked on ADR 0013 / PR #54; not a live authorization or release decision.

Preserve ADR 0011's installed action boundary. `review:request` may append a **recommendation** to retain/reject/correct/qualify an extracted candidate or request evidence. It never promotes findings, marks semantic sufficiency, resolves contradictions, alters originals, approves payment/legal conclusions or enables the future approval scopes. UI labels make this distinction explicit. No canonical permission/RLS migration or customer endpoint is installed; the existing `/v1` and disabled `/v2` contracts are unchanged.

Application review contracts freeze source/representation/parser versions, extraction provenance, case revision, policy, required slots and conflicts in an immutable snapshot. User commands include a stable request UUID, snapshot hash and expected review revision. Trusted server composition derives tenant/actor/access from the existing CaseAccessService and rechecks source bytes through its injected loader. The disposable database adapter additionally rechecks current active permissions (`case:read`, `evidence:read`, `coverage:read`, `review:request`), case/policy and verified source-intent metadata in its transaction. Event, head and receipt commit together; stale input fails; unknown commit acknowledgment is reconciled by the same request UUID. Synthetic UUIDs/loopback session nonces are not real signed-human attestation.

The new `apps/web/review` is a connected **synthetic workbench**, separate from `apps/api/main.py`. It uses source text and codepoint-correct highlights, preserves unsaved edits, handles stale/unknown outcomes, displays append-only history and exports draft packs. Default storage is honestly labeled session memory; real disposable PostgreSQL behavior is verified through the injected repository/service in integration tests. No customer upload, new LLM call, external notification or production deployment.

The draft ZIP includes original bytes, normalized representations/mappings, frozen case data, review history, a readable HTML report and per-file SHA-256 manifest. Trusted offline repository code checks exact file inventory, bounded stored-only ZIP entries, source/version/representation lineage, quotes/locations and the review hash chain without extraction or execution. A separately retained manifest hash binds the pack to an external checkpoint. Self-consistency does not establish authenticity, real reviewer identity, qualified signature, legal validity or approval. Historical entries referencing earlier snapshots are preserved as recommendations; their former source sets are not expanded in a current-snapshot pack.

Source bytes must be freshly checked at review/export through application composition. The present read/export is a best-effort source snapshot, not a production atomic approval or immutable Storage version guarantee. Snapshot and audit hashes are not tamper-proof against a database administrator. Production Auth→least-privilege DB/Vault, complete persisted accepted Kernel graph, action-specific human attestation and actual approval/export policy remain open gates.

Data/access/rollback review: [EI-003](../tasks/EI-003.md). Visual/behavior ownership: DESIGN.md and UX-CONTRACT.md. Revert additive modules and dispose only the ephemeral test database; never drop production tables or rewrite originals.

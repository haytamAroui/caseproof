# KRN-107 — Versioned evidence, coverage and review-note provenance binding

**Status:** Review branch. **Base:** KRN-106 PR #16 (unmerged).  
**Design inputs:** ADR 0008/0009 (still proposed) and v1 `InMemoryProvenanceLedger`.

## Purpose

One append-only trace connects the declared case/scope/policy, required
issues and source processing inventory, immutable captured document/version
and parser-representation fingerprints, exact finding/assessment revisions,
fidelity result, semantic/sufficiency proposals and review-note observations.

No inference of source authenticity, factual truth, human authority,
coverage exhaustiveness or legal effect is made from a complete trace.

## Pure-Python Stage 1 contracts

- `InMemoryProvenanceBridge.capture(tenant, case, policy)` snapshots only
  **privacy-minimized references**: source/version/representation digests,
  declared source state and attempt ID, finding statement digest/revision,
  link and assessment revision, citation/fidelity statuses, assessor
  claim/method/timestamp, issue mapping, issue outcome and typed coverage
  blockers. No raw documents, quotes, statement content or rationale
  are serialized into snapshot or event payload. Source attempts and
  assessor names are unverified *claims*.
- The bridge captures incomplete coverage too; `ordinary_complete` reflects
  the conservative KRN-106 evaluator for the declared scope, **not** the
  truth or completeness of the real-world investigation.
- A deterministic `CaseProvenanceSnapshot.fingerprint` pins all capture
  fields; no fuzzy OCR/statement remapping. Read/read checks reject observed
  scope, link, assessor and source-lineage revision races.
- `record(...)` compares a supplied snapshot to current references and
  appends **only a harmless observation** to the existing per-tenant
  in-memory provenance hash chain. Typed actions are `snapshot`,
  `review_note_proposed` and `review_disagreement_proposed`. There
  is **no approved/authorized state**, and actor reference is prefixed
  `unverified:`. Review note text is not retained in the event or
  receipt; only a domain-separated SHA-256 digest is stored. Low-entropy
  note hashes are not secrecy guarantees.
- Local idempotency key + same semantic fingerprint returns the
  prior receipt even after a later case revision. Same key with different
  payload conflicts. A failed event append leaves no receipt; the
  existing event ID uniqueness and chain verification remain effective.
- `verify_record` checks the locally retained receipt against an
  intact tenant hash chain, exact event kind/ID/sequence/hash, actor
  claim and canonical payload reference. Receipt-preserved event
  truncation and tampering are detectable in tests.

## Explicit non-goals and security warnings

This **is not production audit, transactional or cryptographic integrity
against privileged data-store operators**. If both the chain and local
receipts are deleted/rewritten, the design cannot establish existence
of a missing event. Read/read reconciliation is not a cross-store lock;
an underlying case may change after capture or after an observation.
An observation has no approval, adjudication, promotion or operational
effect. No actual user authentication, reviewer permissions,
tenant RLS, Supabase storage, SQL migrations, durable persistence,
replay recovery or atomic state+audit commit exists in this task.
An attacker with direct Python access could corrupt any in-memory store.

In particular, do not interpret `actor_reference_claim` or model-proposed
`assessor_kind=human` as a trusted principal. Trusted server-side actor,
tenant, policy and action permissions plus immutable durable audit must
be implemented and tested in Stage 2 before an authorized review action.

## Adversarial acceptance and compatibility

- Verified pointer chain from source version through OCR representation,
  current finding/link revision, semantic proposal, required issue and
  coverage manifest.
- Missing/failed source, stale link, wrong quote and contradictory
  support all remain explicitly incomplete or unresolved.
- Re-OCR creates a new representation; prior pointers cannot drift.
- Duplicate idempotency retries, diverging replays and duplicate
  event IDs; intentional event append failure leaves no local receipt.
- Chain payload tampering/truncation, receipt mismatch, cross-tenant
  lookup, malformed actor/policy/review action and UTC timestamp.
- Mutating case or link during snapshot capture fails rather than
  silently certifying a mixed revision.
- Existing v1 provenance and KRN-101–106 interfaces unchanged.
- Locked runner: architecture check, pytest, Ruff, mypy, compileall.
  No deployment or autonomous merges.

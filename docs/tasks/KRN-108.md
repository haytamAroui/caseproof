# KRN-108 — Independent adversarial invariant suite

**Status:** Implemented as tests/fixtures on a standalone review branch from `main`.  
**Scope:** Evidence Kernel stages KRN-101 through KRN-107.  
**Architecture:** Proposed ADR 0008 and ADR 0009; existing Constitution controls prevail.

## Why a separate suite?

The Stage 1 modules each have positive and negative unit tests. KRN-108
adds *cross-module* adversarial tests with **hand-labelled oracle results**,
rather than deriving expected truth from the evaluated implementation.
It exercises the complete synthetic chain:

`immutable source bytes → transformed representation → exact typed anchor →
finding revision → deterministic content fidelity → assessor semantic proposal
→ grounding-policy eligibility → required-issue/source coverage →
provenance snapshot/observation`.

A matching quote and a fully processed declared source may coexist with a
false real-world proposition; this suite never claims factual truth,
verified human review or a legal conclusion.

## Files and reproducibility

- `tests/adversarial/fixtures/grounding_cases.json`: versioned, immutable-in-Git
  expectation matrix with **15 labelled cases**. Intentional baseline includes
  one `model_assessor` case where declared-scope ordinary coverage can
  be true while grounding under policy is false — evidence coverage and
  authorized lifecycle transitions remain **different contracts**.
- `tests/adversarial/test_end_to_end_invariants.py`: pure Python synthetic
  fixtures through public domain APIs; parametric outcomes and seeded
  metamorphic tests for Unicode quote mutation, reparse/representation drift
  and injected hidden links; no live credentials, web calls, LLM or customer
  data.
- The full `uv run --locked pytest -q` CI job already collects
  `tests/adversarial/test_*.py` recursively; the focused invocation is
  `uv run --locked pytest -q tests/adversarial`.

## Gate oracles and attack families

| Mutation | Invariant |
|---|---|
| Change a quote's character, case or whitespace | Exact fidelity cannot match |
| Re-OCR creates a new representation | Old typed anchor remains pinned; naïve ID rewrite is stale |
| Stale source/representation hash or text offset | Grounding fails and completeness cannot be asserted |
| Missing expected source or failed parser retry | Declared case cannot ordinarily complete |
| Add an unlisted contradictory/supporting link | Complete current link inventory required; cherry-picking fails |
| Qualification/inconclusive/contradiction/unassessed | Cannot silently turn an issue into supported ordinary completion |
| New finding statement revision | Old evidence and declared link selector cannot close new revision |
| Label a model as assessor | Cannot satisfy default grounding assessor policy |
| Pretend an exclusion was authorized | Cannot ordinarily complete based on user-authored authority claims |
| Same IDs in different tenant namespaces of **shared stores** | No cross-tenant finding/revision collision, observation reuse or snapshot contamination |
| Reuse idempotency key with changed review note | No second event and explicit conflict |
| Truncate an observation hash chain with retained receipt | New idempotency key cannot create a replacement chain |
| Inject imperative instructions as document bytes | Bytes remain untrusted data, not execution or permission |
| Repeat evaluation of an unchanged reference | Deterministic digest, no hidden event/state mutation |

The synthetic fixture contains no law packs or sector-specific calculations.
Seeded tests use Python's `random.Random(seed)` with fixed seed IDs, so
failures can be replayed without relying on network or mutable models.

## Known limitations / uncovered risks

- **Critical distinction:** `ordinary_complete` is scoped to the
  explicitly declared manifest, not real-world exhaustive discovery.
  KRN-106 does not authenticate `AssessorKind`, so a model-labelled
  support proposal can still appear complete at the declared-scope
  coverage layer. KRN-105's grounding policy separately rejects it.
  No API or production workflow may use coverage alone as approval.
- **Pure kernel reference:** no production tenant authorization/RLS,
  durable object/database storage, actual OCR/PDF parser, legal truth,
  authenticated reviewer, atomic state+audit, access revocation,
  real crash recovery, performance/load testing or malicious-file
  sandbox. Tests of tenant-keyed in-memory registries do **not**
  prove production isolation.
- Assertions on in-memory, locally retained hash-chain receipts are
  tamper-evidence under limited conditions, not anti-truncation or
  independent durable integrity against a privileged attacker.
- A complete happy-path corpus does not show the implementation
  safe from unmodelled adversarial inputs. Run KRN-109 executable
  boundary contracts and Stage 2 integration/fault tests before
  releasing any user-facing workflow.
- This suite is deterministic coverage, not property-testing with
  exhaustive state-space exploration, mutation-coverage metrics or
  a fully independent second implementation.

## Merge and verification

The task is **test-only plus a non-executable JSON oracle fixture and
Markdown specification**, with no kernel runtime or domain logic change.
Run the genuine GitHub Actions locked checks on the final head:
architecture check, full pytest, Ruff, mypy and compilation; cite
run ID and exact counts. Review unusual expected outcomes, especially
model-labelled coverage, as explicit **limitations rather than victories**.
No autonomous merge, deployment or paid resource changes.

# S2-008a2 — Strict typed persistence codec for KRN-102 anchors

**Status:** Proposed source implementation, production-disabled; additive to merged disposable S2-008a proof. No new Supabase migration, cloud DB role, SQL write adapter, route or bucket.

## Scope

The application boundary converts existing **KRN-102 domain locator types** to/from an exact, versioned metadata projection suitable for eventual PostgreSQL JSONB. It does **not** depend on AZComply code or alter the pure Evidence Kernel.

- `apps/api/evidence_locator_codec.py`: encode/decode all four locator kinds (Unicode text spans; PDF physical-page rectangles; spreadsheet stable sheet/A1 ranges; typed JSON object/array paths). Unknown or incomplete schema versions, extra fields, boolean-as-integer values, floating-point PDF geometry, nonfinite JSON, repeated JSON keys and unsupported typed paths are rejected. PDF coordinates round-trip as decimal **strings** to preserve KRN Decimal precision.
- `ExpectedEvidenceParent`: the application must independently obtain tenant/case, opaque document/version/representation IDs and SHA digests from an authorized joined DB query. `decode_anchor_projection` rejects mismatched tenant/case, stale version/representation, SHA drift and unknown metadata keys. Constructing this expected parent from the untrusted input defeats the contract and is prohibited.
- `validate_against_verified_bytes`: optional testable gate requiring separate exact original and derived bytes plus parser-verified layout where applicable. Checks both SHA-256 digests and physical PDF page geometry/rotation, workbook table/sheet/bounds, UTF-8 Unicode code-point offset/normalization or JSON path existence.
- `tests/test_s2_008a2_locator_codec.py`: positive round trips, Unicode and Decimal precision, malformed and duplicate JSON, boolean/integer confusion, cross-case/version mapping, coordinate-basis drift, missing layout/field/table and regression tests. `kernel-boundary.yml` additionally type-checks the adapter.

## Trust limits

A successful metadata round-trip is **not** independent document availability, authenticity, quote fidelity, semantic sufficiency, or approval authority. Byte comparison supplied by the caller is not proof that the caller obtained bytes from a protected immutable vault. Parser-supplied layouts must be independently trusted and bound to the exact representation/version before use.

S2-009 must implement real private immutable bytes, authenticity/availability checks and recovery. S2-007 must deliver actual signed Auth -> least-privilege database authorization. S2-004 must implement a real decision, audit and idempotency writer. The current `/v2` routes remain disabled.

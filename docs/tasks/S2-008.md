# S2-008 — Durable Evidence Kernel graph: CaseProof-native design

**Status:** Proposed, documentation-only; **NO database migration, adapter, Auth connector, storage bucket, v2 route or deployment implemented.**
**Date:** 2026-10-22.
**Primary consumer:** ExceptionDesk supplier invoice ↔ purchase order exception review.
**Future consumer:** CaseProof factual dispute dossiers, through the same sector-neutral evidence graph.
**Governing sources:** `CONSTITUTION.md` C1–C16/C24/C25; `docs/standards/database-v1.md`; ADR 0007–0009; proposed ADR 0010 in PR #27; KRN-101–109 reference implementation; existing S2-002A PostgreSQL 17 migration `20261022001009`.

## Goal and boundaries

An authenticated reviewer must later be able to restart the application, fetch the **same immutable evidence version and exact citation coordinates**, recover each finding/link/coverage revision and its separately attributed assessments, then inspect a **frozen** decision input without falsely equating a quote match, source authenticity, semantic support and approval.

The existing seven-table Stage 2 SQL is a development **foundation**, not the KRN-101–109 persisted graph. `caseproof.document_versions` captures source digest and minimal metadata but currently stores neither immutable representations, validated typed anchor locators nor finding/link/coverage provenance. The current Python kernel registries are pure in-memory reference adapters. A new durable graph must preserve their distinctions, not serialize every object to one mutable JSONB status.

No domain-specific invoice/PO/VAT/credit-note tables, no AZComply schema/code, no embeddings/vector index, no new plugin/agent runtime, and no customer documents are authorized by this task. S2-009 will own durable private bytes and verified object availability; S2-004 will own atomic decisions and audit/idempotency.

## Cross-boundary invariants (MUST survive persistence)

1. **Trusted tenant/case scope.** For every tenant-owned row, use `org_id NOT NULL` and a server-derived `case_id` where applicable. Deny row-level access absent trusted membership and `case:read` plus the relevant action. Never authorize on user-supplied tenant, actor, role, `human_authenticated` or custom libpq session settings.
2. **Immutable captured bytes, distinct parser output.** `SourceVersion` is (document_id, version_id, sha256, exact bytes, UTC ingested_at, media_type). `DerivedRepresentation` is a **different immutable identity**, with representation digest, source digest, parser name/version/config fingerprint, coordinate convention and UTC creation. Re-OCR makes a new representation, never repoints an anchor.
3. **Typed anchored citations.** `EvidenceAnchor` binds exact document, version, source SHA, representation ID and SHA. Persist exactly one of `TextSpan`, `PdfRegion`, `SheetRange` or `StructuredField` with versioned locator schema. Text offsets are zero-based half-open Unicode code-point indices with encoding/normalization; PDFs use physical page and numeric rectangle plus rotation/basis; sheet uses sheet ID/A1 range; structured fields use typed key/index path. No implicit remap.
4. **Four independent assessment dimensions.** Citation resolution and exact fidelity are deterministic computed statuses; semantic relation and link sufficiency are **attributable assessor proposals** tied to exact statement and anchor revisions. A claimed HUMAN assessor reference is not authenticated human authority. PDF region/sheet-range location-only citations cannot claim exact quote match.
5. **Finding and link revision history.** `FindingStatement` has positive integer revision and UTF-8 statement SHA. `FidelityAssessment.finding.statement_revision` currently uses a **canonical decimal string**: persist the integer statement revision and explicitly validate this mapping. Link `(link_id, assessment_revision)` always references an immutable statement revision and one anchored representation; newer assessments never mutate historical rows.
6. **Declared-scope coverage only.** `CoverageManifest` freezes case, scope, manifest and policy versions; `ExpectedSource` supports unknown/missing/pending/processed/failed/excluded; `RequiredIssue` carries acceptance policy, source inventory, linked `(link_id, assessment_revision)`, and relevant findings; processing attempts and exclusions are separate. A manifest does not prove that all real-world sources/issues have been discovered. A completed flag is a *recomputed* projection, never client authority.
7. **Authenticity, availability, corroboration, disposition are distinct.** Source verification revision includes assessor, basis and status. Source availability (S2-009) includes exact object identity/check and can block promotion/export after post-publication loss. Neither substitutes for semantic support or authorized review.
8. **Current-head serialization.** Every publish of a new current finding/link/manifest/representation/**source-verification (authenticity)**/availability/policy head MUST acquire the same case-aggregate lock and advance `cases.case_revision` in the same DB transaction, or a separately reviewed `SERIALIZABLE` strategy with safe retries. An immutable historical append alone need not change a current head; **however, it still requires its own atomic audit event on insertion**. Decision preflight must freeze all heads, including current source-verification, while holding that lock; case CAS alone is insufficient if head writers bypass it.
9. **Actor and audit durability.** **Every persistent evidence insert** (including staged, unpublished representations, source verifications, statements, links, assessments and coverage) requires independently trusted actor identity (or explicitly service actor), append-only event with correlation/causation and safe digest, all inserted in the **same transaction** as its immutable row. Failed audit insertion aborts the staged write even if the row will never be selected as current. Publication additionally atomically records its own head-update audit, case revision and idempotency receipt. No source content, private quotes, credentials, prompt text, personal identity metadata or short-lived signed URLs in audit records.
10. **Fail-closed read/restart.** Data unreadable, missing version, absent object, wrong SHA, unknown locator variant, parser layout drift, stale policy or cross-case FK => unresolved/stale/denied; never auto-correct or return a fabricated positive decision.

## Proposed ERD (logical, NOT DDL)

```text
organizations ── organization_members
    │
    └── cases (aggregate head + policy/scope pointers)
          ├── documents ── document_versions [EXIST]
          │                       │
          │                       ├── source_verification_revisions [NEW]
          │                       ├── source_availability_revisions [S2-009]
          │                       └── derived_representations [NEW]
          │                                    └── representation_layouts [NEW]
          ├── finding_statement_revisions [NEW]
          │              └── evidence_link_revisions [NEW]
          │                           └── evidence_anchors [NEW] ── representation
          ├── coverage_manifest_revisions [NEW]
          │             ├── coverage_expected_sources / attempts [NEW]
          │             ├── coverage_required_issues [NEW]
          │             ├── coverage_issue_sources [NEW]
          │             ├── coverage_issue_relied_links [NEW]
          │             └── coverage_exclusion_proposals [NEW]
          ├── policy_version_bindings [NEW or existing case pointer]
          ├── audit_events [EXIST, append-only]
          └── idempotency_records [EXIST]
```

Square bracket status labels above are explanatory, not SQL names to create without review.

**Identity compatibility:** Kernel `SourceVersion.document_id` / `version_id` and `DerivedRepresentation.representation_id`, anchors, findings and links are **opaque bounded strings** (examples: `v1`, `ocr-1`) and are **not UUIDs**. The existing SQL tables use UUID primary keys. Preserve a **lossless, case-scoped logical ID alongside each internal UUID** (e.g., unique `(org_id, case_id, kernel_document_id)` on documents, unique `(org_id, document_id, kernel_version_id)` on document_versions, unique `(org_id, document_version_id, kernel_representation_id)` on representations), with a trusted mapping layer that round-trips the exact logical spelling. The UUID is only an internal relational locator; content SHA-256 is only byte integrity, **never a substitute logical ID** because equal-byte representations can have distinct identities. On a legacy document row without a logical ID, require an explicit reviewed backfill policy and reject ambiguous mapping; never silently reinterpret the existing UUID as a kernel-facing opaque ID. Ensure source/version anchors join both logical IDs and immutable internal UUID FKs consistently. The initial additive schema must decide whether a logical ID is unique per document+version namespace or per case and cover malicious ID collisions and duplicate same-byte versions in its tests.

**Cross-case referential integrity must be proven, not inferred**: the existing `document_versions` table references documents using (org_id, document_id), while documents carry (org_id, case_id). To bind new evidence to one case, introduce *reviewed additional composite unique keys* on existing parent tables where necessary, then use **both** (org_id, case_id, document_id) → documents and (org_id, document_id, version_id) → document_versions (where the **internal** `version_pk_uuid` is the stored document-version PK, not the kernel's opaque `version_id` nor `version_number`). For evidence anchors also enforce representation source identity and document-case identity across the two paths. Same tenant alone is **not** enough: an anchor to another case in the same organization must fail.

| `evidence_anchors` | org/case, anchor identity, exact source/representation keys and SHA, locator kind, locator schema version + typed validated payload; unique anchor key immutable, no fallback cross-version search | Evidence persistence |
| `finding_statement_revisions` | org/case/finding_id/positive statement_revision, UTF-8 text SHA, private text reference or bounded confidential content, trusted creation event, immutable statement | Evidence persistence |
| `evidence_link_revisions` | org/case/link_id/positive assessment_revision, fixed finding/revision and anchor; expectation kind + typed exact-content fingerprint, computed citation-resolution/fidelity/reason and method, separate semantic relation/sufficiency proposal + assessor kind/reference/method/rationale provenance/UTC; source proof does not imply reviewer authority | Evidence persistence |
| `coverage_manifest_revisions` | org/case/scope_version/manifest_revision, selected policy version, snapshot fingerprint, scope-change reason, immutable created audit event | Coverage persistence |

| `coverage_issue_sources` / `coverage_issue_relied_links` | explicit link tables to in-manifest expected sources and exact finding/link assessment revisions; reject foreign case/manifest/source and stale revision | Coverage persistence |
| `coverage_exclusion_proposals` | source_id, reason, **claimed** actor/permission/audit references; separate *trusted authorized disposition record* is needed before an exclusion is accepted | Coverage / review |
| `source_verification_revisions` | source version, independently assessed origin/authenticity status, method/basis, trusted or claimed assessor provenance, UTC + append-only revision **and creation audit event**; selecting a new current authenticity head advances case aggregate revision and audit atomically | Evidence / provenance |
| `source_availability_revisions` | source or representation object identity/version, verified status and SHA, verifier/basis/recheck time, aggregate head invalidation on loss; S2-009 lifecycle | Evidence Vault |
| `case_evidence_heads` (or explicit equivalent) | case aggregate's current finding/link/manifest/**source-verification**/policy/availability heads with `case_revision` and audit ref; **head update serializes through same case lock**, without mutating historical rows | Application transaction |

The schema must not persist model confidence as authority. Use typed columns for FK/revision/status/digest; JSONB only for versioned, bounded polymorphic payloads such as locator/layout with deterministic typed validation on both read and write. Avoid ordinary JSON floats for decimal PDF coordinates and amount semantics: define canonical representation and verify exact round-trip. SQLite mocks cannot validate PostgreSQL constraints or RLS.

## Decision/transaction strategy to review

**Append-only historical records and current-head publication are different operations:**

- Insert verified immutable evidence/statement/assessment/**source-verification** records after trusted case/membership authorization; each insert's FK and object hash checked against exact parent identity. **At the exact staged insertion, atomically insert a trusted, immutable audit event with actor/correlation/causation and reference it from the new record; fail/roll back the insert if audit persistence fails.** This is required even if the record remains unpublished forever. A staged candidate **must not automatically change the selected case head**.
- Publish a current head (**including a source-authenticity verification head**): acquire active-membership lock then case row lock (stable S2-004 lock order), re-evaluate active permissions, original source/representation availability and relevant frozen scope/policy, validate reference consistency and digest, increment case aggregate revision, publish new head, persist audit/idempotency atomically and commit. A disputed or revoked authenticity head immediately invalidates any frozen approval snapshot; race this against approval in real PostgreSQL tests.
- Evaluate KRN-105/KRN-106 from immutable persisted revisions and **fresh authorized source availability**, not a manually editable `eligible` or `ordinary_complete` row.
- Reviewer approval consumes **exact frozen head IDs + snapshot hash + current verification/availability heads** in an authorized S2-004 transaction; no approval until genuine reviewer attestation and full evidence graph exist.

Concurrent head publisher versus reviewer: one wins, other fails deterministically as stale. Historical content remains readable subject to current authorization and privacy/retention policies.

## RLS / grants / index rationale

- Preserve private `caseproof` schema and explicit deny-by-default runtime privileges. No general-purpose `SECURITY DEFINER` or publicly callable helper. Every new table enables RLS, limits SELECT to independently **real** authorized tenant/case membership and permission; no authenticated INSERT/UPDATE/DELETE or audit read by default.
- Choose and independently review a least-privilege application writer role before granting any INSERT or head update. Synthetic `auth.uid()` tests are not proof of signed sessions. Never use service-role bypass or caller-supplied `SET app.user` as authority.
- Use unique composite keys covering (org, case, identity, revision) to enforce immutable identity and foreign links. Add keyset indexes for (org, case, revision DESC, ID) on history and (org, case, digest) for source retrieval; use targeted FK supporting indexes. Require `EXPLAIN (ANALYZE, BUFFERS)` on realistic anonymized fixture size before further indexes, rather than blanket JSONB GIN or unneeded universal indexes.
- All writes parameterized; read-only object metadata references do not grant download. Object authorization occurs again before signed URL creation, and source bytes are rechecked on use.

## Staged engineering slices (do not skip gates)

**S2-008a — source representations, trusted layout + exact anchors (first).** New independently reviewed *additive* migration, private read-only repository ports, typed round-trip validators against KRN-101–103 and negative PostgreSQL FK/RLS/version drift cases. The storage implementation S2-009 must provide verified byte content; until then permit only synthetic local fixture bytes and **deny promotion/export**.

**S2-008b — immutable finding statements + assessment revisions.** Exact statement/link revisions with separate deterministic fidelity and assessor semantic proposals, full tenant/case FK closure, append-only writes and before/after restart reconstruction. Reject quote from mismatched representation, wrong case and a later statement falsely inheriting old assessments.

**S2-008c — issue/source coverage + current-head serialization.** Complete manifest, required issue/source/attempt/revision/exclusion structure; concurrency test a head/policy/availability writer racing an S2-004 decision, with zero silently successful stale approvals. Recovery must preserve unresolved issues.

**S2-008d — provenance snapshot and review packet reconstruction.** One reproducible fingerprint over exact source/representation/statement/assessment/manifest/policy/availability identities; restart, reassessment and corruption-injection tests. Audit and signed packet require S2-004/S2-009/real Auth gates.

The **first implementation PR** should be bounded to S2-008a schema proposal and disposable PostgreSQL proof—not entire graph at once.

## Mandatory adversarial verification (no synthetic success claims)

| Negative or positive check | Release requirement |
|---|---|
| Own tenant + own case positive fixture | Authorized reader sees correct representation; denies-all fixture cannot pass |
| Cross-tenant **and same-tenant cross-case** | Composite FKs and RLS prevent anchor/link/manifest misbinding |
| Mutation of immutable history | UPDATE/DELETE denied under actual runtime role; **all staged historical INSERTs** require same-transaction append-only audit+correlation, not only current-head publication |
| New OCR output / parser version | New **opaque logical** representation ID even for equal bytes; old anchors remain bound or go stale/unavailable, never silently remap |
| Unicode span / PDF region / sheet range / JSON typed path | Deterministic typed round-trip, exact manifest bounds, hard reject unsupported version |
| Exact quote but contradicted finding | Fidelity MATCHED and semantic CONTRADICTS remain independent; no approved truth flag |
| Source authenticity disputed / object unavailable | Independent status visible; resolution/promotion/export fail closed until reassessment |
| Missing source / unknown expected inventory / excluded issue | Coverage incomplete or explicitly qualified; no silent ordinary completion |
| Graph head change during case decision | All current-head publishers, **including source-authenticity verification**, acquire case aggregate lock + bump case_revision; stale decision conflicts |
| Revoked Auth/member, expired session, compromised role | Deny across reads, object access and writes; genuine IdP vs DB role proofs separate |
| Failed audit or idempotency receipt insert | All state/head writes roll back and replay does not invent success |
| Disconnect/restart, out-of-order events, forged hash | Exact prior revisions reconstruct or operation fails safely |
| Real storage object disappears after metadata publish | Append availability event, invalidate head/coverage and block export even after loss is recorded |

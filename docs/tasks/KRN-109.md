# KRN-109 — Executable v2 boundary contracts and transition/error matrix

**Status:** Stage 1 implementation PR; not a live API, deployment or production signoff.  
**Base:** `main` after KRN-108 PR #18.  
**Design references:** Proposed ADR 0008 and ADR 0009 and informational
`contracts/kernel-api.v2.proposal.json`.

## Implemented boundaries

- `apps/api/contracts_v2.py`: strict Pydantic 2.0 boundary models for
  text/PDF/spreadsheet/structured locators, immutable source/representation
  hashes, unapproved candidate creation, evidence-link proposals, guarded
  promotion requests, business-exception proposals, coverage and structured
  errors. Runtime model validation **rejects extra user-controlled fields**,
  including `tenant_id`, `actor_id`, `role`, `approval_authority`,
  `authorized` and `lifecycle_status`.
- Locator discriminants and typed representation identity are explicit. Source
  bytes, target statement revisions, and semantic assessments are not
  conflated into a `verified` boolean. A PDF region with no trusted parsed
  quotation remains metadata only under KRN-103.
- `draft_openapi()`: deterministic **OpenAPI 3.1 proposal** constructed from
  the actual Pydantic validators via `model_json_schema`, not an
  unvalidated prose-shaped approximation. It is **not registered** with
  FastAPI; generated descriptions and 200 response placeholders illustrate
  design only and must never be interpreted as functioning endpoints.
- `contracts/v2_operation_matrix.json`: versioned manifest of six proposed
  routes, model names, required application permissions and 401/403/404/
  409/422 error mapping, plus exact trusted/untrusted authority boundaries.
- `promotion_preflight()`: **read-only synthetic server-facts test double**,
  returning typed denial codes or `APPLICATION_REVIEW_REQUIRED`. It is
  intentionally incapable of returning approval, changing state, persisting
  an audit event or executing a request. Production trusted principal/context
  and case facts do not yet exist.
- `tests/test_v2_api_contracts.py`: parameterized schema validation,
  malformed coordinates, ambiguous typed source values, forbidden authority
  fields, optimistic policy/version conflicts, invalid transitions, incomplete
  coverage, insufficient reviewer permissions, unavailable audit, idempotency
  mismatch, formal route/schema coverage and explicit assertion that **no v2
  routes are exposed by the current development FastAPI application**.

## Lifecycle and authority distinction

Only the sequence
`candidate → evidence_grounded → review_ready → approved_conclusion`
is described. No arbitrary jumps, backward transitions or direct user-set
status are accepted. `approved_conclusion` requires an authenticated human
with application-resolved permission and frozen, complete, conflict-free
evidence and policy-level sufficiency **in the future real application**.
The current synthetic `VerifiedPrincipalForTest`/ `AuthoritativeFactsForTest`
objects deliberately **do not authenticate anyone** and cannot authorize
anything. Even positive preflight returns only an instruction for a future
trusted application to re-check and commit atomically.

Policy scope and role are read from the server's own verified context,
never from request metadata, client headers or alleged model confidence.
Missing authentication maps to 401; access-masked cross-tenant resources
to 404; insufficient permission to 403; stale revisions, disallowed
transitions, insufficient coverage, idempotency collision or audit failure
to 409; malformed, unknown, or client-authority fields to Pydantic 422
when served by a future route adapter.

`BusinessExceptionRequest` is distinct from approval. Accepting an
operational exception must never change evidence fidelity or create an
`approved_conclusion`; no execution handler exists yet.

## Known limitations and stage gate

This contract slice does not implement HTTP /v2 endpoints, actual identity
verification, tenant RLS/ACL, trusted policy loading, immutable durable
version storage, idempotency result retrieval, transactionally co-committed
audit, source authenticity, parser/OCR, legal determinations, case exports
or production safe concurrency. `draft_openapi` includes **proposed**
responses because runtime adapters and durable write semantics do not
exist. It is not a deployed or live contract.

Pydantic field-level validation is necessary but insufficient to establish
coverage correctness or claim support. KRN-106's declared-scope ordinary
coverage alone **cannot** grant approval (see KRN-108 model-assessor case).
No environment or LLM-driven actor may directly construct the synthetic
trusted-context test double as a substitute for authenticated server state.

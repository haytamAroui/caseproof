# KRN-102 — Typed, version-bound evidence anchors

**Status:** Implementation PR (pending independent review and ADR 0008 approval)
**Parent implementation:** [KRN-101 PR #10](https://github.com/haytamAroui/caseproof/pull/10)
**Architecture:** [ADR 0008 proposed in PR #8](https://github.com/haytamAroui/caseproof/pull/8)

## Accepted reference-slice scope

A citation must resolve to an exact, immutable document version and independently identified parser/OCR representation, with both SHA-256 digests; the resolver accepts only a trusted tenant scope injected by the application.

Typed locators:

- **TextSpan:** strict UTF-8, zero-based half-open Unicode **code-point** offsets; normalization declared by the anchor and *validated*, never silently applied. Invalid UTF-8, normalizations or ranges fail closed.
- **PdfRegion:** zero-based physical PDF page index, unrotated PDF-point bottom-left coordinate system, positive finite `Decimal` page width/height and bounded rectangular region; exact page dimensions and rotation checked against a trusted per-page manifest.
- **SheetRange:** stable sheet ID plus strict uppercase A1 range and optional stable table ID; checked against a trusted workbook sheet extent/table catalog. The display sheet name is not a stable identifier.
- **StructuredField:** typed path of string object keys and nonnegative integer array indices with explicit schema ID; checked against exact UTF-8 JSON representation, rejecting duplicate JSON keys and invalid constants.

`LayoutManifest` attaches trusted parser metadata to exactly one immutable representation identity and digest. It can only be registered once per tenant/representation. An absent, stale, ambiguous, wrong-tenant or wrong-type manifest prevents PDF, workbook or structured-field citation resolution.

`ResolvedAnchor` records only a **located region/path**. A text span or JSON path yields its exact extracted value; PDF/workbook locators yield no extracted content and cannot assert quote/value fidelity. KRN-103 is the separate citation fidelity check. A matching citation proves neither truth nor authenticity nor semantic support nor legal effect.

## Security and implementation limits

This is **pure Python** and in-memory. It assumes a trusted parser adapter supplied PDF/sheet/schema layout metadata and a trusted authenticated caller supplied tenant scope; **there is no PDF parser, spreadsheet reader, verified layout derivation, persistent storage, access-control implementation, RLS, malware scanning, file-size bounds, or private storage in this PR**. Do not accept client-uploaded layout metadata as trusted. Bytes and resolved values are deliberately excluded from diagnostic `repr`. Do not log private source content. Production scope enforcement and integrity of parser-derived manifests belong to Stage 2/3.

No existing HTTP v1, `SourceReference`, `DocumentVersion`, `EvidenceWorkflow`, schema, migration, package dependencies, or deployment behavior is modified.

## Acceptance tests

1. Unicode emoji and decomposed diacritic offsets locate exact code points rather than bytes or UTF-16 offsets; stale and out-of-bounds spans fail.
2. Wrong source hash, representation hash, version, representation ID or tenant never falls back to another source or OCR output.
3. Invalid PDF page/rotation/dimensions/region or missing manifest fails; coordinates are tied to the physical page.
4. Unknown sheet IDs, reversed or outside-bounds A1 ranges and wrong table IDs fail.
5. Missing JSON fields/array indices, schema mismatch, duplicate keys or invalid JSON fail.
6. All locator and manifest dataclasses are immutable and no `ResolvedAnchor` representation logs private values.
7. Existing v1 contracts remain untouched and full locked architecture, pytest, Ruff, mypy and compilation checks pass on the final commit.

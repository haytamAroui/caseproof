# KRN-103 — Independent citation resolution and content fidelity

**Status:** Feature implementation PR; not merged or released.
**Parent:** [KRN-102 PR #11](https://github.com/haytamAroui/caseproof/pull/11)
**Design authority:** [Proposed ADR 0008 in PR #8](https://github.com/haytamAroui/caseproof/pull/8)

## Why

The fact that a locator resolves does not prove that a quote or typed value matches, and even an exact match is no proof the corresponding finding is factually or legally correct. Resolution, content fidelity, semantic relation and sufficiency must never collapse to one `verified` flag.

## Scope

Implement a pure Python, deterministic `FidelityEvaluator` producing an immutable assessment bound to one `FindingRevision` and `EvidenceAnchor`.

- **Citation resolution:** `resolved`, `unresolved`, `stale`, `invalid`. Missing identities in the trusted tenant namespace report the same unresolved outcome regardless of whether the identity exists in another tenant; known identity with wrong immutable digest is stale. Out-of-bounds, mismatched coordinate basis or missing/invalid trusted layout manifest is invalid. Neither unavailable content nor a malformed locator is a content mismatch.
- **Content fidelity:** `matched`, `mismatched`, `indeterminate`. Exact UTF-8 text span comparisons are case-, whitespace- and Unicode-sensitive and use the previously declared offset/normalization basis. Exact JSON values compare both scalar **type** and value to avoid `true == 1`. This reference slice supports strings, integers, booleans and JSON null; floating-point JSON, compound JSON values, unsupported expectation/locator pairs and locations without extracted value remain indeterminate.
- **PDF/spreadsheet location-only:** KRN-102 resolves physical PDF bounding boxes and spreadsheet ranges against trusted layout metadata but has no independently extracted text/cell value. KRN-103 therefore **never claims fidelity matched** from a location-only citation, even if a caller supplies an expected quote.
- **Semantic relation and sufficiency:** always `not_assessed` in this evaluator. Future KRN-104 requires a separate explicitly versioned semantic assessment against the *exact finding statement*, and future promotion may not infer semantic support from citation fidelity.
- **Result metadata:** stable reason code, deterministic method version, finding ID/revision and source+representation identity via the anchor. No expected source content is embedded in result or diagnostic representation.

## Explicit limitations

This is **not** a source authenticator, legal-rule engine, fraud detector, semantic evaluator, independent PDF/workbook parser, durable evidence store, authorization boundary, or audit trail. Tenant namespace is an in-memory reference; a trusted application must verify caller rights at use time. Hashes prove consistency against captured bytes, not authenticity. No confidence score establishes review authority.

This slice does not alter existing v1 HTTP contracts, API schemas, financial calculations, migrations, external providers, dependencies, or storage.

## Adversarial acceptance

- Quote faithfully present while finding is false: `matched` fidelity; semantic `not_assessed`.
- False quotation at valid location: `resolved` with `mismatched` fidelity.
- Re-OCR or changed representation digest without a new anchor: `stale` / `indeterminate`; never silently remapped.
- Missing and cross-tenant identities: uniform `unresolved` / `indeterminate`.
- Wrong offsets, bad UTF-8, unsupported normalization, absent layout, invalid JSON: `invalid` / `indeterminate`.
- Boolean versus integer and string versus number: fidelity mismatches despite Python equality or cast possibilities.
- PDF geometry or worksheet range without extracted content: `resolved` / `indeterminate`, never `matched`.
- Finding revision changes: assessment bound to the new revision, semantic still not assessed.
- Locked GitHub Actions checks: architecture, full pytest, Ruff, mypy, compileall.

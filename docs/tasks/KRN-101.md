# KRN-101 — Immutable source versions and derived representations

**Status:** Implementation branch — not reviewed or merged
**Branch:** `feature/krn-101-source-representations`
**Proposed design:** [ADR 0008 in PR #8](https://github.com/haytamAroui/caseproof/pull/8)
**CI prerequisite:** [PR #9](https://github.com/haytamAroui/caseproof/pull/9) is the base of this stack and must be merged/approved before this implementation PR.

## Problem

An exact quotation is not a stable citation unless the original source version and the parser/OCR representation it was extracted from are individually identifiable and immutable. Reparsing cannot silently change an existing anchor's coordinate basis. A hash of captured bytes establishes integrity, not author authenticity or factual truth.

## Bounded scope

- Pure Python `SourceVersion` with immutable source bytes, document/version identity, SHA-256 digest, media type and UTC ingestion timestamp.
- Pure Python `DerivedRepresentation` with its own immutable bytes/digest; parent document/version and parent hash; parser/transform name, version and configuration digest; coordinate convention; UTC creation timestamp.
- `InMemorySourceRegistry` with trusted-tenant namespace keys, duplicate-ID rejection, parent lineage verification and exact representation-to-source lookup for the next KRN-102 slice.
- Adversarial tests: changed bytes/digest; wrong parent version or parent digest; cross-tenant reads; duplicate version/representation identity; re-OCR with new IDs and preservation of old outputs; empty identifiers; bad hash, bad timestamp and incompatible input type; v1 compatibility.
- No changes to preexisting v1 `EvidenceWorkflow`, `DocumentVersion`, `SourceReference` or HTTP v1.

## Out of scope

- KRN-102 typed text/PDF/spreadsheet anchor coordinates and anchor resolver.
- Authorization of callers, persistence, object storage, encryption, RLS, durable audit, ingestion limits, parser sandboxing, signed URLs, deletion/retention enforcement, re-OCR remapping or actual parser adapters.
- Evidence fidelity, semantic support, coverage aggregation, review promotion, truth verification or legal/finance outcomes.

**Security boundary:** `tenant_scope` is a trusted application-input precondition, **not** a client-supplied authorization field. The registry's isolation is an in-memory structural invariant; production access control belongs in Stage 2. Bytes are suppressed from dataclass repr; do not log source content.

## Acceptance

1. An old source version or representation cannot be overwritten or redirected.
2. Registration validates digest against the exact stored immutable bytes.
3. Every derivative resolves only when its parent version and digest match inside a trusted tenant namespace.
4. Re-OCR/reparse creates a separate representation ID; no fallback or implicit reassociation.
5. CI records genuine `uv run --locked` architecture, pytest, Ruff and mypy outcomes. Avoid invented passing claims.

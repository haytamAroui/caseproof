# KRN-105 — Policy-versioned candidate grounding gate

**Status:** Review-branch reference implementation; no merge or deployment.
**Parent:** KRN-104 [PR #14](https://github.com/haytamAroui/caseproof/pull/14).
**Relevant decisions:** ADR 0008 (source/anchors and link assessments) and ADR 0009
(coverage/promotion), both marked *Proposed* in the checked-in repository.

## Goal

A candidate is not evidence-grounded merely because it contains a quotation,
or because a model proposes that an excerpt "supports" the finding. The
candidate-to-evidence-grounded gate must evaluate the **whole current finding
snapshot** and **all current link revisions**, rather than selecting a favorable
subset or silently ignoring a contradiction.

This is **read-only eligibility**, not a state machine or an authorized
promotion command. It deliberately contains no `promote`, `approve`,
`commit`, `send`, `export` or irreversible action.

## Implementation contracts

- `GroundingSnapshot`: finding ID, current statement revision/hash and the
  complete sorted list of current `(link_id, assessment_revision)` pairs.
  Caller-supplied truncated snapshots fail closed as stale.
- `GroundingPolicy`: immutable version ID, minimum eligible links, permitted
  *assessor kinds*. In this reference implementation models cannot satisfy the
  grounding gate even if a model's proposal says `supports` or `sufficient`.
  Permitted kinds are HUMAN or DETERMINISTIC, and a self-described HUMAN
  record is **not proof of a verified human identity or authority**.
- `GroundingGate.snapshot` resolves the registered latest finding revision
  and complete latest link set. `evaluate` compares optimistic input
  preconditions to live in-memory state, failing closed for stale versions
  or omitted links.
- Every current link must remain resolvable in the caller's trusted tenant
  namespace, have KRN-103 `resolved + matched` fidelity, and contain
  a **recorded** non-`not_assessed` semantic relation from a kind allowed
  by the policy. The required count is an additional minimum.
  Out-of-bounds, missing, changed or inaccessible evidence fails closed.
  Statement, KRN-103 fidelity and KRN-104 assessment history are immutable.
- Contradictions are allowed in `eligible` **only because evidence-grounded
  means evidence has been attached and explicitly assessed, not that the
  unqualified finding is supported, true or approved**. The result explicitly
  discloses both currently contradicting links and links with any historical
  contradiction, including after later reassessment.
- Reasons are typed and explanatory, never a single `verified` boolean.
  `eligible` is a prospective check. It neither decides sufficiency at
  the claim/coverage-policy level nor authorizes a workflow transition.
- A same-statement link may be reassessed by a new append-only revision; an
  altered statement requires a new statement revision and new evidence links.

## Adversarial acceptance tests

Positive: a faithful quotation contradicting a deliberately false finding can
be evidence-grounded with contradiction disclosed (never approved).
Reject: no links, not_assessed semantic relation, unmatched quote, wrong/stale
source representation, deleted source, model-only proposals, partial/stale link
inventory, superseded statement, insufficient eligible-link count, invalid
policy/snapshot, cross-tenant lookups and spoofed policy assessor configuration.
Re-evaluation is side-effect-free; no source value is exposed in gate results.

## What the tests cannot establish

- Actor identity and effective role/permissions: `HUMAN` is an untrusted
  attribution from KRN-104. Model output is not authority. A real application
  must validate this against authenticated, trusted server-side context.
- **Effective policy version:** this gate accepts an explicitly provided
  versioned policy, but only the future authorized application can decide
  which policy is currently in force.
- Atomicity: changing the ledger between snapshot and commit is possible.
  Here the gate has no commit; a Stage 2 transaction must atomically
  revalidate the snapshot and write the lifecycle state and immutable audit
  event with idempotency checks.
- Durable security: this in-memory tenant-keyed reference does not enforce
  production authorization, RLS, storage retention or tamper-resistant audit.
- Fidelity limits: KRN-103 cannot prove PDF-region or spreadsheet-range
  content fidelity from a layout-only citation; such citations do not
  satisfy this gate without new trusted extraction/assessment machinery.
- No coverage/issue completeness or reviewed final conclusion is established.
  KRN-106 will add the required issue/source coverage ledger.

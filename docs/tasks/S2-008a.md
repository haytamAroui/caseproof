# S2-008a — Disposable source representation / typed-anchor schema proof

**Status:** Implementation reference PR only. **NOT a canonical Supabase migration**, runtime writer, private Evidence Vault, authenticated user proof or deployed customer feature. Parent design: `docs/tasks/S2-008.md` (merged); `docs/adr/0010-stage2-native-durability.md`. All source bytes below are **synthetic digest metadata**, with no source blob in storage.

## First bounded slice

- `db/proposals/S2-008a_disposable_representation_anchor_graph.sql` proposes new *test-only* tables under the private `caseproof` schema. Additional composite parent keys enforce that even two cases in the **same organization** cannot cross-link source identities. Source logical IDs (`invoice/source-A`, `v1`, `ocr-1`) are preserved as opaque text separately from internal UUID primary keys. Distinct parser representations may have the same SHA-256 bytes. Audits are referenced on every immutable appended row. Append-only DB triggers block ordinary rewrites. All new tables have RLS enabled and **zero authenticated table grants**, so normal user SQL receives no rows/permission errors.
- `scripts/verify_s2_008a_database.py` executes the schema **only** on the pre-existing, localhost-only disposable PostgreSQL service guarded by `_isolated_postgres_env()` from S2-007. Verifies tenant+case parent FKs, source fingerprint binding, equal-byte/different-logical-ID round trip, missing audit reference denial, same-tenant other-case anchoring denial, aborted insert/audit rollback, immutable update/delete denial and unapproved user read denial.
- `tests/test_s2_008a_disposable_schema.py` and `.github/workflows/kernel-boundary.yml` ensure CI runs this test after S2-002+S2-007+S2-004 in the **same ephemeral PostgreSQL 17 database**. No credentials, real user UUIDs or remote Supabase resources are involved.

## Explicit incomplete contracts

1. **Bytes not verified.** The schema stores digest metadata only. Until S2-009 provides immutable stored bytes, origin hash read-back, parser outputs and availability-state recovery, NO anchor is resolvable and NO promotion/export may use these records.
2. **Polymorphic layout/locator validation incomplete.** SQL checks known kinds, bounded JSON objects, schema labels and composite references but not trusted PDF geometry, Unicode code-point bounds, spreadsheet sheet/tables or structured JSON paths. A trusted KRN-102 validator must reject invalid coordinates and exact manifest mismatches **on every read and write**. Future DDL may add kind-specific constraints.
3. **Audit FK is necessary, not sufficient.** Every staged evidence insertion must create/commit its own independently trusted audit event **in the same transaction**; a FK alone does not establish that an existing event belongs to this insertion. The disposable test demonstrates one transaction failure rollback, not privileged production writer enforcement. Future least-privilege writer and event ownership/operation fingerprint constraints are mandatory.
4. **RLS is deny-all on new tables.** There is intentionally no positive authorized runtime read. S2-007 must review real signed Auth -> actual application DB role, positive/negative permissions and removal; do not weaken the RLS to make tests superficially pass.
5. **No live migration approved.** DDL is a `db/proposals/` fixture, not tracked by Supabase CLI or `supabase/migrations`. Before any migration: independent security/architecture review, explicit human approval, CLI-generated migration file, additive forward migration + rollback/recovery plan, separate live environment verification and no source/PII in logs.
